## Goal

GoFront v1.8.0 ("Portable Go completion") makes every language feature behave the same in `js`, `wasm` and `both` packages. It adds a Go-source stdlib, `encoding/json` in WASM, and Go 1.23 iterators, and it completes `gofront/simd` (SIMD adoption has its own plans: SIMD Skinning and [`simd-collision-plan.md`](simd-collision-plan.md)). SimpleFPS is a mature hybrid engine with strict zero-allocation hot paths, so most of v1.8.0 is **not** something it needs to adopt. The release does carry two real consequences:

1. **A measured regression, mostly fixed upstream.** Strict-mode runtime panics (GoFront Tasks 0.16a/b, Phase 0.7) route the JS output of every `both` package through bounds-checked `__at`/`__ix` helpers and `__nilcall` guards. `mathx` is SimpleFPS's only `both` package, and every frame of the JS renderer runs through it. On GoFront `2d9d774` the unchanged JS half of `mathx` is **3.6× slower on `Mat4Multiply`** and **3.2× slower on `Vec3.TransformMat4` and `BoundingBox.TransformInto`** (*Re-audit* rows). GoFront follow-up-fixes Task 1.2 now elides constant slice indexes after a `_ = xs[15]` hint or a `len` guard, and with hints in `mathx` every gated entry is within 1.10 except `Vec3.TransformMat4` (1.10–1.13), which still pays one `__nilcall` per pointer access.
2. **A small set of clean-ups.** The `min`/`max` builtins in WASM (GoFront Task 0.11, Phase 0.6) replace six hand-written helpers in `collision`. Three stale GoFront workarounds can go: the `toggleDebug` callback in `engine`, `hasDepth` in `rendering` (a zero `map` field is now `nil` in `js` packages) and the `_shTri = shTri{}` literal in `collision` (zero-value package-level arrays now work in WASM).

This plan bumps SimpleFPS to v1.8.0 without regressing the zero-allocation or throughput invariants. It adopts the clean-ups and records every v1.8.0 capability that is deliberately not adopted, with the reason. `gofront/simd` needs data-layout changes in `animation` and `collision`, so it is planned separately: skinning in SIMD Skinning (completed on 1.7.0) and collision in [`simd-collision-plan.md`](simd-collision-plan.md) (after this plan).

**Done means:**
- `package.json` depends on `gofront@^1.8.0`, and `npm run test:all` (unit, DOM, Playwright smoke) passes with no test changes other than those listed in this plan (Task 1.2's `float32` golden in `spatialhash_test.go`, Task 2.4's `hasDepth` test).
- `npm run test:perf` passes on v1.8.0 (raycast ≤ 3,000 B new-space delta per 100k casts, controller ≤ 0.5 B/frame in `tests/perf/zero-alloc.js`).
- `tests/perf/mathx-js.js` A/B benchmark (v1.7.0 vs v1.8.0 compiler, same source, `mathx` compiled as `both`) shows a B/A time ratio of **≤ 1.10** on `Mat4Multiply`, `Mat4Invert`, `Mat4FromRotationTranslationScale` and `BoundingBox.TransformInto`, and **≤ 1.15** on `Vec3.TransformMat4` (its remaining cost is GoFront's per-access nil check, P1b), as the median of 5 process runs.
- `node tests/perf/js-vs-wasm.js --ab --repeat 5 --max Infinity --gate 'mesh-parse>=0.80'` (v1.7.0 vs v1.8.0 compiler) shows no hybrid entry more than 10% slower (mesh-parse 25%). The harness reports A time / B time, so > 1 means v1.8.0 is faster: the default 0.90 floor is the 10% slowdown gate, and `--max Infinity` keeps a speedup from failing the default 1.10 ceiling. A 10% gate is the tightest that measured noise allows (A/A spread up to 6.4% per run). It catches the 2–3× strict-mode regression, but not a 3–9% drift.
- Negative and parity cases pass: short-slice panic parity on `[js]`/`[wasm]` (`app/src/engine/mathx/mat4_test.go`), NaN degenerate ray (`app/src/engine/collision/spatialhash_test.go`), the field-pointer guard (`app/src/engine/engine_test.go`) and the depth-state case (`app/src/engine/rendering/rendering_test.go`).
- `collision` has no hand-written `min*`/`max*` helpers and no `_shTri` composite-literal workaround, `rendering` has no `hasDepth` flag, and `engine.toggleDebug` no longer uses the callback workaround.
- `AGENTS.md` and `docs/architecture.md` are updated, and each phase has its `CHANGELOG.md` entry.

## Scope Rule & Boundary Matrix

A v1.8.0 capability is adopted only if it (a) removes a verified SimpleFPS workaround, or (b) beats the existing code on a benchmark without breaking zero-alloc. A capability that only adds expressiveness is not adopted.

| Category | Rule | Examples / Members | Reason (Excluded rows) |
|---|---|---|---|
| **In scope: core** | Toolchain bump with regression gates on every target | `gofront@^1.8.0`; array value semantics, accessor-ref pointers, per-iteration loop vars, universe scope and JS slice views (no source change, guarded by tests/benchmarks); strict-mode checks in `mathx` JS output (gated by the new benchmark) | |
| **In scope: target-specific** | Adopted where it replaces existing code | `min`/`max` builtins in `collision` (WASM), `scene.lightgrid`, `game.weapons` (JS); `&d.Field` pointers in `engine` (JS); `nil` zero `map` fields in `rendering` (JS); zero-value package-level arrays in `collision` (WASM); `gofront/simd` → SIMD Skinning, [`simd-collision-plan.md`](simd-collision-plan.md) | |
| **Excluded: runtime / platform** | Breaks a SimpleFPS invariant | `iter.Seq` / range-over-func and `slices.All`-style iterators on hot paths; `encoding/json` in WASM; changing `mathx.Mat4` to `[16]float32` | Iterators allocate a yield closure per call breaking zero-alloc; JSON parses are one-offs at load time via fast native `JSON.parse` (moving to WASM adds boundary copies); `[16]float32` copies on every assignment/call under v1.8.0 value semantics requiring rewriting the entire JS renderer |
| **Excluded: deferred** | Valid, but no consumer today or planned separately | Complex numbers, generic type aliases, `fmt` `%T`/`Sprint`; reslice allocation in `rendering`; `gofront/simd` in collision (exported SIMD fields now build); GoFront nil-check hoisting (P1b) and the `TransformMat4` gate back to 1.10; v2.0.0 native-engine adoption | No current consumer in engine; a reslice is still a `Proxy` view, so `DrawList` stays; SIMD collision planned in dedicated [`simd-collision-plan.md`](simd-collision-plan.md); P1b is upstream work, tighten the gate when it lands; native engine adoption planned post-v2.0.0 |
| **Excluded: removed upstream** | GoFront v1.8.0 no longer provides it | `bufio`, `net/url`, `context`, `encoding/csv`, `container/*`, `hash/{adler32,crc32,fnv}`, `crypto/{hmac,md5,sha1,sha512,subtle}`, `log`, `math/rand/v2` (GoFront portable-go D2, "lean stdlib") | Not available to adopt; SimpleFPS imports none of them (`grep` of `app/src` imports, 2026-10-29) |

## Approach

### 1. Architecture & Design Decisions

- **The bump comes first, and it is gated by measurement.** The A/B harness from SIMD Skinning compiles the same source with two compilers (`GOFRONT_BASELINE_DIR` = 1.7.0, current = 1.8.0) and interleaves them in one process, so there are no machine-dependent baselines in git. The same harness can re-measure each upstream GoFront phase before the tag (`GOFRONT_DIR=../gofront`); that check is manual and not a task here.
- **New benchmark `tests/perf/mathx-js.js`.** It compiles `engine/mathx` as the `both` package it is (no `forceTarget`; strict mode exists only for `both`, see *Verified Gaps*) and times the JS half: `Mat4Multiply`, `Mat4Invert`, `Mat4FromRotationTranslationScale`, `Vec3.TransformMat4` and `BoundingBox.TransformInto` (gated), plus `Vec3.Add`/`Normalize` (report-only, since A/A noise on sub-10 ns entries reaches 1.38×). It interleaves A and B over 9 rounds of 2M calls, runs through `tests/perf/ab.js`, and fails if a gated entry's median B/A time ratio over 5 process runs exceeds 1.10. With no baseline compiler configured, it skips.
- **Strict mode in `mathx` is resolved upstream, not worked around locally.** `mathx` must stay `both` (shared by the JS renderer and the WASM physics). The slice half of the upstream fix (prerequisite P1) landed as GoFront follow-up-fixes Task 1.2: a constant index `k` skips its check once the function has proven `len(xs) > k` with the hint `_ = xs[k]` or a `len` guard. SimpleFPS adds `_ = out[15]; _ = a[15]; _ = b[15]` at the top of each `Mat4*` function, which is idiomatic Go and is also BCE-friendly under real `gc`. **The proof is per identifier**: where a function indexes an alias (`BoundingBox.TransformInto` does `m := matrix`), the hint goes on the alias after it is declared (`_ = m[15]`). The nil half of P1 (one check per pointer per function, no check on a method's own receiver) did not land; it is P1b.
- **Decision rule for the bump.** The gates are ≤ 1.10 on every gated entry, except `Vec3.TransformMat4` at ≤ 1.15: with hints it measures 1.10–1.13, and its remaining cost is six `__nilcall`s per call that only P1b removes (1.03 without them). The 1.15 band is the user's decision of 2026-10-29; tighten it to 1.10 when P1b lands. If an entry still exceeds its gate after the hints, the bump does not merge: SimpleFPS stays on `^1.7.0` and the numbers go upstream. GoFront's own release gate (no hybrid-raycast regression above 3%) runs in WASM and does not cover the JS renderer path, so SimpleFPS has to enforce this itself.
- **`min`/`max` replace helpers, without changing semantics on finite input.** Go's `min` on floats propagates NaN, while `a < b ? a : b` returns `b` when `a` is NaN. Collision inputs are finite triangle coordinates, so behaviour on real geometry is unchanged. The NaN case gets its own test so the difference is a deliberate, recorded change rather than an accident.

**Rejected alternatives:**
- *Splitting `mathx` into `mathx` (js) and `mathxw` (wasm).* This duplicates 1,900 lines and breaks the single-source invariant from the v1.6.1 adoption.
- *Asking upstream to make strict mode opt-out per package.* The GoFront plan rules this out explicitly ("the checks are never shipped disabled").
- *Hoisting `Mat4` elements into locals by hand.* `Mat4Multiply` already reads `a` into locals (`let [a00, …] = [__at(a, 0), …]`) and still measures 3.0×: every read is checked once, and there is no cheaper form without an elision proof.

### 2. Invariants & Safety Bounds

- **Zero per-frame allocations:** `tests/perf/zero-alloc.js` thresholds stay as they are.
- **`mathx` stays `both` and keeps no mutable package state**, as required by AGENTS.md.
- **The boundary API is unchanged:** no exported signature in `collision`, `physics`, `animation` or `decoder` changes.
- **Generated assets are untouched.**
- **Single source of truth for numbers:** gates compare A and B in the same process; this document records the measured ratios.

### 3. Edge Cases & Error Handling

- **Shadowed `min`/`max` locals:** in `rayAABBInterval` (the only function left that declares them), rename `min`/`max` to `lo`/`hi` *before* introducing the builtins. Otherwise the builtin silently resolves to the local `*mathx.Vec3`, and the result is a type error or, worse, a valid call to the wrong thing.
- **NaN through `min`/`max`:** add a `spatialhash_test.go` case for a degenerate ray (NaN direction component) that asserts the query returns 0 hits without panicking, on both the old and new helpers.
- **The mesh-parse watch item:** resolved on `e3a1a62` (0.989×) and on `2d9d774` (0.997×). If it returns on the tagged release, bisect GoFront from `f69c67a` and file the result upstream. It is load time only, so it does not block the bump unless it exceeds 25% (the `--gate 'mesh-parse>=0.80'`).
- **JS slice views:** if the Playwright smoke test or a DOM test fails on 1.8.0 in code that reslices a plain array (e.g. a `Proxy` view reaching a browser API that rejects it), stop and report it upstream against GoFront Task 0.20. Do not rewrite SimpleFPS around it.
- **Hints on aliases:** a hint on a parameter does not cover an alias of it. Task 1.4 hints the identifier that is indexed; `grep` for `:= <Mat4 param>` in `mathx` before adding hints.
- **Noisy `Mat4FromRotationTranslationScale`:** two 5-run batches on the same build gave 1.04 and 1.39. If Task 1.4 sees it above 1.10, re-run the benchmark before treating it as a gate miss; with hints it has no bounds check left, only ten nil checks (`q` ×4, `v` ×3, `s` ×3).
- **`float32` printing:** any other golden built from `%v`/`%g` of a `float32` changes the same way as Task 1.2's; only `TestSpatialHashGridCharacterization` does on 2026-10-29.
