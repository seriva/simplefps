# Changelog

All notable changes to this project will be documented here.

Format: [Keep a Changelog](https://keepachangelog.com/en/1.0.0/)

## [Unreleased]

### Changed
- **Final WebAssembly split: `animation` runs in WebAssembly.** `BinaryReader` moved from `systems` to `assets`, and `ParseBinaryAnimation` from `animation` to `assets` (next to `ParseBinaryMesh`), so `animation` imports only `mathx` and is now `//gofront:target wasm`. `Skeleton.ComputeSkinningMatrices(pose)` no longer returns a `[]mathx.Mat4` (which the boundary would copy out every frame); it writes the palette into `animation.SkinMatrices`, a `gofront/shared` buffer JS reads in place, and returns the joint count (capped at `animation.MaxSkinJoints` = 64 = `rendering.MaxJoints`). New `tests/perf/js-vs-wasm.js` (`npm run bench`) compiles `physics` and `animation` both `--js-only` and hybrid and reports throughput (Node 25, run to run): raycasts 1.1–1.15× JS, FPS-controller fixed step 2.3–2.4× (≈105k vs 45k frames/s), 64-joint skinning frame 1.1–1.3×. `app.wasm` is ≈100 kB unoptimised, ≈80 kB after `--release`. Requires the GoFront fix that gives handle methods with `int` parameters their boundary trampoline (previously `Pose.SetJointTransform` from JS threw `Cannot convert 0 to a BigInt`); the same fix makes the controller loop allocation-free (0.2 B/frame, was ~48).
- **Physics runs in WebAssembly.** `engine/physics` (`FPSController`, `DynamicBody`) is `//gofront:target wasm`, so the controller and projectile steps and all their raycasts stay inside WASM. The static world raycaster moved into WASM as `collision.StaticWorld` (`Scene.StaticWorld()`); `Scene` no longer implements `physics.RaycastProvider` itself, and `Scene.RaycastStatic` delegates to it. `FPSController.Camera` is now a WASM-owned `CameraPose` value: `game` copies the camera in before the fixed steps, moves with the new `MoveWithCamera(strafe, move, dt)` and copies position/up back after `SyncCamera`. Physics constants are typed literals (`Gravity` = 785.6). The physics heap-growth guard moved from `physics/integration_test.go` to `tests/perf/zero-alloc.js`, which now also drives the controller loop across the boundary. Requires the GoFront v1.6.0 boundary (interfaces and WASM → JS closures).
- **WebGPU is the sole graphics API and `rendering` is WebGPU-native.** The `rendering/webgpu` package is merged into `rendering`; the generic `RenderBackend` interface, `PipelineState` presets, `any` resource handles, `SetUniform` and the runtime pipeline/bind-group caches are gone. `rendering.Backend` (`backend.go`) is a typed wrapper over `GPUDevice`/`GPUQueue`/`GPUCanvasContext` with one command encoder and one `queue.submit` per frame. Every render pass is an explicit `GPURenderPassDescriptor` (`renderpasses.go`); every `GPURenderPipeline`/`GPUComputePipeline` is baked once in `Renderer.Init` (`pipelines.go`) with a cull-disabled twin for double-sided materials. WGSL (`wgsl.go`) shares a four-slot bind-group contract — frame, material/pass inputs, object, lighting — where per-draw data lives in a 256-byte-slot `ObjectRing` bound with a dynamic offset and flushed in one `writeBuffer` per frame (`objects.go`). Skinning matrices go through a `BoneRing` storage buffer indexed by `ObjectData.misc.x`, dynamic lights through a `lights` storage buffer (up to 256), so the shaders have no fixed bone or light slot counts. Particle emitters are simulated on the GPU by a `particle-update` compute shader inside the frame's compute pass and drawn with one instanced draw; the Kawase blur for the light and emissive buffers runs as a compute pipeline writing to storage textures. `engine.Init(onReady)` drops the `preferWebGPU` flag and requires `navigator.gpu`.
- `rendering.Drawable` loses the `*Shader` parameters and gains `Simulate(r, computePass)`; entities fill an `ObjectData` slot via `Renderer.NextObject()` and draw through `Renderer` helpers.
- Headless tests render real frames against `rendering/fakegpu`, an in-memory `GPUDevice` written in Go that records buffers, textures, pipelines, bind groups, passes, draws, dispatches, writes and submits. The `rendering`, `scene`, `engine` and `assets` suites assert on pass order, pipeline selection, `ObjectData` contents, storage-buffer uploads and resource counts, and keep their heap-growth guards. The Playwright smoke test mocks WebGPU with a Proxy device when no GPU is available.
- **Collision runs in WebAssembly.** The old `engine/physics` package is split three ways: `engine/mathx` (`Vec3`/`Mat4`/`Quat`/`Transform`/`BoundingBox`, `//gofront:target both`), `engine/collision` (`Trimesh`, `Octree`, `Ray`/`RaycastResult`, `//gofront:target wasm`) and `engine/physics` (`FPSController`, `DynamicBody`, JS, calling into `collision`). Every other package now imports `mathx`/`collision` directly; `BoundingBox.GetTransformMatrix()` is gone in favour of the out-parameter `TransformMatrix(out)`. `gofront build` emits `app.wasm` next to `app.js`. Requires `gofront` ≥ 1.5.1 for the zero-allocation JS→WASM boundary (exports bound as constants, references as `externref`, panics via `env.panic`). `gofront test` runs dual-target verification on `mathx` (`[js]` and `[wasm]`) and executes `collision` tests (including new `collision/integration_test.go`) in WebAssembly. `tests/perf/zero-alloc.js` now loads the hybrid bundle and measures ~3 KB of new-space growth over 100k raycasts. On the official Möller–Trumbore benchmark (131,072 triangles, 100,000 rays), hybrid throughput reaches **31,293 rays/s (1.17× JS)** with **0.86 B/ray** allocation — completing the v1.5.0 Phase 6c go/no-go milestone as a clear **GO**.
- **Rewrote SimpleFPS in [GoFront](https://github.com/seriva/gofront).** Every engine and game module under `app/src` is now a Go package or `.templ` component compiled by `gofront`; no JavaScript remains in the app source. The module layout is preserved 1-to-1: `engine/{physics,systems,animation,rendering,scene,assets}`, `game/`, and `main.go`. Design decisions and phase history are in `docs/plans/archive/gofront-rewrite-plan.md`.
- Hot paths (physics step, raycasts, render passes, HUD) are zero-allocation: out-parameter math (`Vec3`/`Mat4`/`Quat`), caller-provided query buffers, fixed-capacity entity/active lists with swap-remove, package-level scratch state, and cached-DOM HUD writes. Heap-growth guards in the `physics`, `rendering` and `scene` test suites enforce this.
- UI (`menus`, `loading`, `hud`, `console`, `stats`, `virtual_input`) is authored in `.templ` with a plain Go state machine; `Reactive.js` is gone. All CSS lives in `app/style.css` so `gofront dev` hot-swaps it.
- Build tooling switched from Microtastic to GoFront (`dev`, `build --pwa`, `prep`, `check`, `test`, `test:dom`), using recursive `app/src/...` package patterns. `gl-matrix` removed; `peerjs` bundled via GoFront's vendor bundler; `jsdom` added for `--dom` tests. Requires `gofront` ≥ 1.3.10 (`^1.3.10` pinned): release builds depend on its `assetExtensions` project option to ship the engine's binary formats and on the `--mangle` free-global fix.
- Test suite: `gofront test` (headless and `--dom`) across all packages, `tests/perf/zero-alloc.js` (`npm run test:perf`, 100k raycasts < 64 KB new-space growth) and a Playwright smoke test `tests/e2e/smoke.spec.js` (`npm run test:e2e`, WebGPU boot → menu → lit frame, with a Proxy-mocked `navigator.gpu` when headless). `npm run test:all` chains everything.
- Documentation (`AGENTS.md`, `README.md`, `docs/roadmap.md`) updated for the GoFront platform; rewrite plan archived.
- Render state is described by typed enums (`MaterialMode`, `BlendFactor`, `DepthFunc`, `CullFace`, `Topology`, `BufferUsage`, `ColorMask`) baked into the pre-built pipelines; double-sided materials switch to a pipeline's `CullOff` twin, so a translucent double-sided group no longer re-enables culling for the rest of the pass.
- `scene.Entity` is now just `GetBase() / Update() / Dispose()`; drawing is a separate concern and only the concrete types that render implement `rendering.Drawable` / `LightDrawable`. Mesh-only state left `EntityBase`: drop-shadow heights and skinned re-sample tracking live in a `Shadow shadowState` field and the ambient probe sample in a `Probe probeCache` field on `MeshEntity` / `SkinnedMeshEntity` (`ReceiveShadow` and the base `TriangleCount` copy were dropped). The scene keeps typed visibility buckets for meshes and skinned meshes (`VisibleMeshes()`, `VisibleSkinnedMeshes()` replace `VisibleEntities(type)`), so probe sampling, drop-shadow raycasts and transparent sorting run without type assertions.
- The renderer requires a scene: `Renderer.Render` skips the frame when any input is nil instead of each pass branching on `scene != nil`, and `engine.Start()` now returns `ErrNoScene` (also logged to the console) when `engine.ActiveScene` is unset. `RenderOptions` is documented as the only path settings take into rendering (filled once per frame by `engine.RenderFrame`). Engine comments describe the Go code rather than the JavaScript files it was ported from.
- `docs/rendering.md`, `docs/scene.md` and `docs/networking.md` are consolidated into `docs/architecture.md`: package layout and dependency rules, boot and frame loop, backend abstraction and `PipelineState`, the pass table (targets, state, shaders, scene lists), `Entity` vs `Drawable`, scene API and per-frame visibility, animation/physics/systems/assets/game summaries, networking, the zero-allocation rules under GoFront, console commands and the test matrix. `README.md` and `AGENTS.md` link to it.

### Removed
- The `Renderer: webgpu` line of the stats overlay, `StatsOverlay.SetBackendName` and `rendering.Backend.Name()`; with a single graphics API the row carried no information. The smoke test asserts the WebGPU boot through the console log instead.
- The WebGL2 backend (`rendering/webgl`, GLSL shaders) and the WebGPU/WebGL backend abstraction (`RenderBackend`, `PipelineState`, `Shader`, UBO pools, `ReadPixels`).
- The unused `ShadowBlurIterations` / `ShadowBlurOffset` settings (the WebGPU drop-shadow pass never blurred).
- All legacy ES6 modules under `app/src/` and the Microtastic/`gl-matrix` dependencies.
- Archived feature plans for the ES6 engine (`docs/plans/archive/*`, except the GoFront rewrite plan); the roadmap keeps their summaries as plain rows.

### Fixed
- Debug bounds boxes (`drawBounds` / `drawLightBounds`) drew 2 of every 3 edges wrong: `Shapes.BoundingBoxMesh` is already a 24-index line list, but it went through `Mesh.DrawWireframe`, which re-pairs indices as triangle edges. It is now drawn directly with the line-list debug pipeline.
- Boot stops with a "WebGPU required" dialog (reload offered) when `navigator.gpu` is missing or the adapter/device request fails, instead of continuing into asset loading with a nil backend.
- Particle instance buffer: the WGSL `Instance` struct was 32 bytes (padded `vec3`) while the vertex layout and buffer allocation assumed 24, corrupting every instance after the first; the struct is now six scalars.
- `SkinnedMesh.Draw` / `DrawWireframe` skip skinned draws for meshes without joint data instead of binding the static vertex layout to the skinned pipeline.
- Debug console commands `tbv`/`twf`/`tlv`/`tsk` were never registered outside tests; `ConsoleManager.ExecuteCmd` also accepts the legacy call syntax (`twf()`, `rscale(0.5)`).
- WebGPU backend: shader modules carry a `label` so bind-group layouts resolve; textures recreate on image upload with full mip chains; `GenerateMipmaps` never encodes into an open pass; depth compare state and lightmap vertex attribute binding fixed.
- `Ray.IntersectTrimesh` no longer boxes a `float32` per cast (writes `Ray.Result` directly).
- Octree `Insert` rolls back an unused subdivision and `RemoveEmptyNodes` compacts in place.
- Several GoFront compiler bugs surfaced by the port were fixed upstream in 1.3.7–1.3.10 (pointer receiver typing, imported struct literals, `sort.Slice` index semantics, `rand.Float32` type, multi-assign temporaries, generic-vs-index parsing, minifier regex misdetection, SVG namespace in `.templ`, minifier mangling of free globals in call arguments, release-build asset whitelist).

## [2026-09] — Legacy JavaScript engine

Final iteration of the ES6/Microtastic codebase before the GoFront rewrite. Highlights, all carried over into the Go port:

- 120 Hz fixed-timestep accumulator decoupling simulation from refresh rate.
- Quake-style `FPSController` step-climbing, iterative wall sliding and multi-height depenetration.
- Two-level BVH, light contribution culling, pooled transparent sorting, shadow raycast budget, compact light UBO layout.
- Backend optimisations: cached scalar uniforms, VAO-baked index buffers, persistent Kawase ping-pong framebuffers, WebGPU bind-group cache eviction on resize, full mip chains for immutable textures.
- Zero-allocation fixes across entities (SoA particles, pre-allocated scratch matrices, pooled sort entries) and GPU resource disposal for emitters and skinned meshes.
- Completed feature plans moved to `docs/plans/archive/`; project made versionless.
